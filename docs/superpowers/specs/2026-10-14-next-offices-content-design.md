# 通判、同知、知府剧情与案件扩充方案

日期：2026-10-14。状态：用户已批准，已按顺序接入并验收；结果见《案件来源与剧情扩充_v0.16.md》与《扩充验收_v0.16.md》。

## 1. 已确认的要求与当前基础

用户已确认范围为现有开放的通判、同知、知府。要求补剧情、事件、案件；案件从 GitHub 现成库取材；采用金庸风格；事件尽量不重复，最多重复一次。

当前源码与 README 显示本地版本 v0.15、存档 v11，工作区保留大量既有未提交修改。三任均为156周，各有8条固定公文；知府另有2件独立案件，通判与同知没有同等的案件办理入口。本轮按当前工作区扩充，保留既有成果。

“最多重复一次”定义为同一次仕途存档内，同一事件累计最多出现两次。新剧情、主线与独立案件采用更严格的一次上限；不以改标题、换人名或换职务绕过去重。案件取证、复核、执行是同一卷宗的阶段，不视作重复立案。新的开局是新的仕途，不与别的存档共享消耗记录。

## 2. 方案选择

建议采用“有限手写事件库＋职务主线＋可追溯公案改编”：数量与事实可以验收，读档不会变案，叙事能连续承接。

另外两种做法：只扩写原24条公文，改动较小，但后半任的内容密度仍不足；运行时随机生成事件，变化较多，但难以可靠验证情节去重、固定证据和来源。两者都不采用。

每任26件事件包括8条主线和18件新增事务，案件另计。每年均安排新内容，新开完整任期中新事件的间隔目标不超过8周；严苛难度的随机周次通过队列排程消除碰撞。条件不满足时采用该事件的适用分支，或按明确期限移入队列，不无限等条件。

同周到来的主线、案件与回报进入可见待办队列，处理一个不会覆盖另一个。月底粮务、养护等常例结算保持为经营行为，叙事只在实际出现新事实时发新事件。案件原则上在任期前中段立卷，给取证、复核和执行留足时间。

## 4. 三任主线与新增事件题目

主线人物沿用现有人物身份，补入船头、匠人、经承、铺户等地方人物。前任办过的事进入后任时呈现新的后果，不重新播放原始冲突。

### 通判：一舟粮，几家命

主线由争粮额、湿粮、运损、拖解、枯水、仓价、重复征收延伸至离任对账。主角逐渐发现同一条粮路上，真实损耗、私售、错记和地方胥役盘剥彼此交错，须分别查清，不能一律归罪船户。选择影响后续证人信任、协作和可取得的凭据；具体账目仍以经营状态结算。

新增18题：夜泊芦汀、船头的旧债、驿口留灯、两副仓秤、雨后晒场、冰封前的最后一船、短脚夫的伤、被扣的路引、米行借仓、船帮约价、孤户解粮、旧册失页、盗粮者的家属、落水后的货担、换班仓役、逆风报程、回乡船票、粮路交接人。

这些事务分别围绕救人和运输延误、雇工结算、夜间接驳、度量校核、临时晾晒、封冻路线、工伤接济、通关凭据、借仓责任、船价谈判、困难户解粮、档案追索、涉案家属救助、事故货物核验、岗位交接、真实在途报告、船户回乡和新任接手展开。与独立案件同题时只作案件入口，不能再奖励一次独立结案。

### 同知：水来之前

主线围绕联防堤、填料、跨县灾民、以工代赈、渡口、赈册、催工与养护。匠人指出险情，乡绅要求护田，灾民要求活路；曾帮过的船户和役户带来新线索。主角既要筹款，也要决定何时停工、返工和分洪。人物对白与河工的实测、验收、口粮和安置记录相连。

新增18题：泥中竹签、老匠不肯签名、石场赊账、堤上的童子、夜雨换班、庙前粥棚、借来的渡船、被淹的祖坟、巡堤犬吠、分洪前的一封家书、工棚药钱、失踪的役夫、裂缝后的复验、上游捐木、下游的水尺、收割与河工、迁居后的第一亩田、汛后匠籍。

题目分别落实为勘测标记、验工责任、材料交付、随工家属、值守轮换、赈食管理、临时运力、墓地迁移、巡查警讯、分洪告知、患病工人、人员核查、工程复验、受益分摊、水位记录、农忙减役、复耕核验和工匠交接。失踪役夫作为来源案件入口，搜寻结果不能凭选项直接生成。

### 知府：堂前灯，堂外人

主线保留丰灾县分款、能吏疑账、水口上诉、政绩核验、护道、城乡取舍、考语和交接；增加地方人情与办事压力。前任结下的人情会影响谁愿作证，但事实和正确审查标准不因关系改变。结局分别回访粮路、河堤、属县和案件执行，让前任选择留下可见后果。

新增18题：晨鼓未鸣、门房截状、旧友来请、驿使催报、乡绅寿宴、孤证与众口、书吏告假、县印暂缺、商会联保、秋闱前的欠粮、告状人的路费、巡察途中、牢中病者、保人的悔意、乡学新生、失火的公廨、属官临别、离任前的最后一灯。

内容分别对应急报听取、诉状登记、私人说情、呈报期限、馈赠边界、证言核对、岗位代办、印信交接、护道责任、应试家庭困难、申诉便利、现场巡察、羁押救治、保证责任、教育成果回访、档案抢救、属官考语和未结差事交接。

## 6. 文风样稿

叙事借鉴金庸作品的动作和对白节奏、人物情义、层层揭疑与地方风物。人物各有利益和口气；官署外有船帮、商号、匠人，官署内有账、权责和人命。金额、工期、成本与真实效果留在选项说明，读者不必从文学修辞猜数值。

> 暮雨初歇，渡口的篷灯还在风里摇。老船头解开蓑衣，从怀中取出半张湿透的运单，平平放在案上。纸上朱印尚清，收粮数目却被人添了一笔。
>
> “少了多少？”你问。
>
> “册上少四十石。”老船头道，“船上，一石也不曾少。”
>
> 经承冷笑：“你一张嘴，抵得过三处画押？”
>
> 老船头没有争辩，只将右手伸到灯下。虎口裂着新伤，掌心还有封仓麻绳勒出的血痕。“小人的嘴不值钱。大人肯看一看昨日的封记么？”

这是一则入口样稿：封记尚未查验，叙述不提前证明船户清白。后续按真实证据分别处理错记、运损或侵吞，人物说法与事实可以不一致。

## 7. 接入、去重与兼容

1. 分离府任内容定义与执行逻辑，沿用现有公账、精力、属县协作、工程、责任和复核记录。新增事件的描述、成本、真实结果及延迟回报对应实际结算，不只播放一段文字。
2. 在仕途总存档保存已消费事件计数、来源题材标识和主线分支。新内容默认上限1；确有新的常例事务需要再遇时显式上限2，并写出第二次的新事实。池耗尽进入常例事务，不随机重放旧剧情。
3. 取证、复核与执行另留卷宗阶段标识，防止重复领粮、重复回款、重复增加政绩。三任主线承接通过新事件ID表达，并复用先前选择的事实记录。
4. 排程使用队列并记录入队和处理状态；严苛难度浮动周次冲突时，后移到可用周或同时入队，不能用 `find` 静默丢掉第二条事件。
5. 新存档版本迁移接续v11。旧档已有选择与结果保留，已过去的事件不补发、不补奖；新增案件在未来适用窗口出现。临近任末的旧档不集中塞入四案，按剩余任期安排后续内容，并保存适用版本，避免用新数量门槛追罚旧档。
6. 当前工作区已有的v0.15修复原样保留。内容稿、源码和构建同步；本轮不包含上线任务。
